# 果实编辑器 · 工作流 v4 设计

> 参考另一位开发者的技能编辑器形态（浮动卡片 + 具名端口 + 彩色链路），
> 节点与端口按《果实弹珠》的真实运行时重新设计，不再对旧模块图做「翻译层」。

## 1. 为什么要重构

七段流水线是「编辑视图 → 旧 graph」的适配层，它把一个有并行分支的 DAG 压成一条列表链。
实测（冰霜果实，10 节点 / 8 边）：

| | 节点 | 边 | onCast | onHit | 延迟 | 路径持续伤害 |
|---|---|---|---|---|---|---|
| 原始图 | 10 | 8 | 1 | 2 | 无 | 无 |
| 七段往返后 | 10 | 9 | 2 | 4 | 1s | 有 |

只要在七段视图里改一个数值，果实行为就被悄悄改写。根因是三层表示不等价：
七段（列表）/ 节点图（DAG）/ 编译器（靠拓扑猜归属、猜命中、猜延迟）。v4 只保留一层：
**端口化节点图就是唯一真相，编译器按端口确定性地产出运行时结构。**

## 2. 五条业务泳道 + 一张事件卡

| 泳道 | 卡片角色 | 可选类型 | 回答的问题 |
|---|---|---|---|
| 触发 | 触发卡 | source | 什么时候放 · 放几次 · 朝哪打 |
| 目标 | 目标卡 | select（单体） / range（范围） | 打谁 · 单体还是范围 · 怎么挑 · 打几个 |
| 投递 | 投递卡 | projectile / motion / targeted / zone / aura | 用什么形式送出去 |
| 表现 | 表现卡 | fx / particles / impact | 看起来发生什么 |
| 结算 | 结算卡 | damage / element / status / mark / shield / split / echo | 最后算什么（最右一列） |
| 事件 | 技能事件卡（右侧悬浮，不是泳道也不是节点） | — | 命中 / 撞墙 / 消失 / 持续 各自再做什么 |

另外两张固定卡：**属性卡**（写 `skill.mods`，不再作为 stats 节点参与连线）、**延迟卡**（`delay`，只影响它下游的结算时机）。

## 3. 端口契约（游戏专属）

三类端口：

- `exec` 执行（橙色实线）：顺序执行 / 继续
- `data` 数据（蓝色虚线）：施放信号 / 目标集合 / 弹体句柄 / 路径点 / 判定区
- `event` 事件（紫色实线）：命中 / 撞墙 / 消失 / 持续

| 卡片 | 输入 | 输出 |
|---|---|---|
| 触发 | — | `施放`(exec) · `施放信号`(data) |
| 目标 | `施放信号` · `执行` | `目标集合`(data) · `执行` |
| 投递·投射物 | `执行` · `目标集合` · `施放信号` | `弹体`(data) · `路径点`(data) · `命中`(event/onHit) · `撞墙`(event/onWall) · `消失`(event/onExpire) · `继续`(exec) |
| 投递·范围 | `执行` · `目标集合` | `判定区`(data) · `范围内目标`(data) · `命中`(event) · `继续` |
| 投递·位移 | `执行` · `弹体` | `弹体` · `撞墙`(event) · `结束`(event) · `继续` |
| 投递·指向 | `执行` · `目标集合` | `弹体` · `命中`(event) · `消失`(event) · `继续` |
| 投递·区域/光环 | `执行` · `判定区`/`弹体` | `实体`(data) · `持续`(event/onCast) · `继续` |
| 结算·伤害/元素/状态/印记 | `命中`(event) · `目标集合`(data) · `持续`(event) · `执行` | `继续`(exec) |
| 结算·护盾 | `执行` · `目标集合` · `持续` | `继续` |
| 结算·分裂 | `命中`(event) · `弹体`(data) | `弹体`(data) |
| 结算·回响 | `执行` · `命中` | `执行` |
| 表现·特效/粒子 | `弹体` · `路径点` · `命中` · `目标集合` · `执行` | `继续` |
| 表现·爆发 | `命中` · `判定区` · `路径点` | `继续` |
| 延迟 | `执行` | `执行` |

**连线规则**（引擎侧校验，不靠用户记）：
1. 类型必须一致（exec↔exec / data↔data 且数据种类相同 / event↔event）。
2. 事件输出只能接「会消费该事件」的输入（例如 `持续` 只能接持续型结算）。
3. 一个输入口可多入，`执行` 输入口单入；输出口可扇出。
4. `执行` 链禁止成环（延迟不能绕回自己上游）。
5. 旧图没有端口的边保留为「隐含连边」，首次打开时按编译语义补齐端口（结构固化）。

## 4. 语义显式化（消灭「猜」）

| 旧实现 | v4 |
|---|---|
| 归属靠 `upstreamHost` 上溯 | 结算卡归属于它连的那张投递卡（端口即归属） |
| 事件组靠 `triggerEvent` 默认值 | 事件由「连的是哪个事件端口」决定；卡片上的触发事件改为只读展示 |
| 命中判定靠 `AUTO_HIT` 推断 | 由投递形态决定，并在卡片上写明「投射物命中 / 范围命中 / 弹珠碰撞 / 必中直击」 |
| 延迟靠全图最长路径 | 只沿 `exec` 端口传播，且卡片上标出累计秒数 |
| 路径持续伤害靠 BFS 路由 | 「路径点」端口连到勾选持续伤害的结算卡，即为显式路由 |

每张卡片底部固定一条**语义条**：`事件 命中 · 宿主 投射物「火球」 · 延迟 0s · 判定 投射物命中`。
这条语义条读的是编译器真实输出（`compile().semantics`），不是编辑器自己再算一遍。

## 5. 编译契约（运行时不改）

`compile()` 继续产出今天的 `C`（`events` 四事件桶、`hosts`、`select`、`stats`、`_views`、`_delay`、`_pathDot`、`_hitKind`），
因此 `game.js` / `skill-effects.js` / 2V2 / 联机快照 / 试放沙盘一律不动。

新增 `C.semantics.byNode[id] = { event, hostId, hostLabel, delay, hitKind, pathDot, routed }`，
作为编辑器语义条的唯一数据源。

端口化编译（阶段二）：
1. 沿 `exec` 端口求可达与延迟；
2. 事件桶 = 该节点挂接的事件端口（`hit→onHit` / `wall→onWall` / `expire→onExpire` / `tick→onCast`）；
3. 宿主 = 上游最近的投递卡（沿 `data.entity` / `event` 端口）；
4. `hitKind` = 投递形态；
5. 旧边无端口时走一次性解析器，解析结果写回 `graph.edges`。

## 7. 卡片上的字段（先精简，再在卡片内下钻）

每张卡片默认显示 4–8 个主参数（滑条 + 数值）；点卡片底部「全部参数 ⌄」后，**在该卡片内部**展开完整 schema 表单（含下拉 / 勾选 / 颜色 / 文本 / 贴图上传 / 特效专属参数），展开区自带滚动，不再需要跳到右侧属性栏。
主参数按类型预先声明（`CARD_FIELDS`），不再把 30 个字段一次性铺在画布上；展开时卡片加宽到 340px，并按展开高度重新错开同泳道卡片。

## 8. 实现状态（本次落地）

已落地：
- `skill-ports.js`：5 条业务泳道 + 1 条事件角色（右侧悬浮卡）、19 种卡片规格、三类端口与 `canConnect` / `inferPort` / `autoLayout`；
- `skill-modules.js`：`compile().semantics.byNode` 作为画布语义条唯一数据源；
- `admin.js`：浮动卡片画布（端口 / 彩色边 / 主参数字段 / 语义 chips / 事件总线卡 / 自动排布 / 缩放 / 泳道归位 / 端口连线与撤销 / 卡片内展开全部参数 / 点线删除 / 目标+范围合并）；
- `admin.css`：深色点阵画布、泳道带、卡片与端口样式、可点击边线、卡片内展开区、合并入口；
- `tools/test_skill_ports.js`（契约 649 项）、`tools/smoke_studio.js`（无头 Edge：渲染 + 端口连线 + 卡片内滑块 + 点线删除 + 展开区编辑 + 目标/范围融合 + 缩放）。

目标 + 范围融合（本次）：
- `range` 从「投递」泳道移入「目标」泳道，角色改为 `target`，与 `select` 共用同一个类型下拉：单体 / 范围；
- `range` 新增「挑选规则」（距离最近 / 最远 / 血量最低 / 最高），编译进 `rangeDescriptor.pick`，`targetsInRange` 先按该规则排序再按「敌人数量」截断；「目标上限」改名「敌人数量」；
- 目标卡下游直接连着一张独立范围卡时，卡片里出现「下游是独立的范围卡 · 合并成一张」：把选择对象 / 挑选规则 / 数量写进范围卡、目标卡的入线改挂到范围卡、删除目标卡（可撤销）；合并后 `C.select` 用范围卡上的口径兜底，避免退回默认值；
- 「添加模块」列表不再单独提供范围入口，统一从目标卡的类型下拉进入。

列顺序（本次）：泳道改为 触发 → 目标 → 投递 → 表现 → 结算，「结算」是最右一条业务列；「事件」不再占一条泳道，改成右侧悬浮的「技能事件」卡（施放 / 命中 / 撞墙 / 消失四桶计数），画布上只画 5 条泳道带。

验收结果：55 套测试 52 通过 / 3 既有失败（test_fx_loop、test_max_skills、test_proj_gap_trail，均与本次改动无关）；无头冒烟 0 控制台报错：
- 端口连线 8→9 条，延迟卡由「未接入」变「已接入」，撤销后回到 8 条；
- 卡片内滑块 0.35→7.15，卡片数不变（没被重绘打断）；
- 点边线 8→7 条，撤销恢复 8 条；
- 结算卡展开 26 个字段，展开区内滑块 20→247 可正常修改；
- 目标+范围合并：10 张卡 → 9 张、连线 8→7，范围卡上的挑选规则 / 敌人数量继承目标卡的 nearest / 4，撤销后回到 10 张；
- 列顺序：画布只有 5 条业务泳道带（触发 / 目标 / 投递 / 表现 / 结算），技能事件卡悬浮在最右侧，不再占列。

尚未落地（明确留给下一阶段）：

- 旧图迁移脚本 `tools/migrate_ports.js`：把 8 个果实的隐含边固化成端口边并逐条比对编译语义；

- 运行时的四个事件桶（onCast / onHit / onWall / onExpire）与参考图的「暴击 / 击杀」尚未扩展对应。
